# pipeline — 파이프라인

## 단계
| 단계 | story-work | 입력 | 출력 | 게이트 | 실패 시 복귀 |
|---|---|---|---|---|---|
| P1 리서치 | 1 + 2 ⏸ | 대상 화면, 키워드 | 레퍼런스 모음, 반영 항목 목록 | G1 | → P1 (키워드를 바꿔 다시 수집) |
| P2 설계 | 3 | 반영 항목, prd.md | 화면 설계 문서 | G2 | → P2 |
| P3 컨셉 | 4 + 5 👤 | 설계 문서, design.md | Figma 키스크린 + 본인 승인 | G3 | 반려 → P3 |
| P4 제작 | 6 | 승인된 키스크린, design.md | 토큰, 컴포넌트, 완성 화면 | (없음, P5에서 판정) | |
| P5 검수 | 7 ⏸ | 완성 화면, rules.yaml | 검수 결과 | G5 ★N1·N2 | → P4 또는 P3 |

G4는 의도적으로 없다. P4 결과는 P5의 G5가 판정한다.

## G1 통과 조건 (멈칫 "반영 기준 없음"을 셀 수 있게 바꾼 것)
- 레퍼런스 5장 이상, 모두 uibowl URL
- 반영 항목 3개 이상. 항목마다 다음이 모두 채워져 있음
  1. `source_url`: p1-references.json에 있는 URL
  2. `story`: U1~U5
  3. `kind`: 레이아웃 / 입력 방식 / 영수증 표현 / 아카이브 중 하나
  4. `content`: 반영할 내용
- 하나라도 빠지면 → P1

## G5 복귀 규칙
| 위반 | 복귀 | 이유 |
|---|---|---|
| design.md 값·서체 위반만 | P4 | 값만 고치면 됨 |
| N1·N2 위반이 하나라도 | P3 | 화면 구조가 틀림 → 컨셉부터 다시 |

## 복귀할 때 파일 처리
- 복귀 단계(Pn)와 그 이후 단계의 파일을 `work/S*/_archive/{시도번호}/`로 옮긴 뒤 다시 작성한다
- P3로 돌아가면 `p3-approval.json`도 옮긴다 → 다시 승인을 받아야 G3 통과
- 복귀가 아닌 경우 통과한 단계의 파일은 덮어쓰지 않는다

## 반복 제한
같은 게이트에서 3번 실패하면 멈추고 본인에게 묻는다.

## 실행 단위
한 번에 화면 1개. 다른 화면이 진행 중이면 새 화면을 시작하기 전에 확인받는다.
